## Задание 1 (день 26): локальная LLM

Модель: **qwen2.5:3b** (1.9 ГБ, q4) через **Ollama** — CPU-инференс ~17–20 ток/с на Intel Ultra 5 125H.
(Пробовала сначала qwen2.5:1.5b — на диалоге с памятью и арифметике врёт, 3b решает оба пункта и остаётся крошечной.)

Как проверить (снять на видео):

1. Установить Ollama: `winget install --id Ollama.Ollama` (уже установлено)
2. Запустить сервер: `ollama serve` (порт 11434) — либо просто открыть приложение Ollama
3. Скачать модель: `ollama pull qwen2.5:3b`
4. CLI-доступ: `ollama run qwen2.5:3b "Скажи одним предложением: локальная модель работает?"` → осмысленный ответ
5. HTTP API + 4 запроса разной сложности: `.\local-llm-demo.ps1`
   - запрос 1 (простой): «Как тебя зовут?» → «Меня зовут Qwen»
   - запрос 2 (диалог, 3 сообщения): модель помнит «Меня зовут Алекс» → «Ты Алекс, а я Qwen»
   - запрос 3 (посложнее, арифметика): 12 конфет → половина брату, треть остатка подруге → верный ответ 4 с пошаговым решением
   - запрос 4 (объяснение): «что такое кэширование, как для школьника» → понятная аналогия
   - под каждым ответом: время, промпт/ответ-токены, ток/с
6. HTTP API можно дёргать и напрямую:
   ```powershell
   Invoke-RestMethod -Uri http://localhost:11434/api/chat -Method Post `
     -ContentType 'application/json; charset=utf-8' `
     -Body '{"model":"qwen2.5:3b","messages":[{"role":"user","content":"Привет!"}],"stream":false}'
   ```
   (есть и OpenAI-совместимый эндпоинт `http://localhost:11434/v1/chat/completions`)

### Проверка через Postman

Всё уже установлено (Ollama + qwen2.5:3b), нужно только поднять сервер: `ollama serve` (если не запущен — окно сразу не закрывается, сервер работает, пока оно открыто).

1. Новый запрос → **POST** `http://localhost:11434/api/chat`
2. **Body → raw → JSON**, вставить (Content-Type Postman выставит сам):
   ```json
   {
     "model": "qwen2.5:3b",
     "messages": [
       { "role": "user", "content": "Привет! Как тебя зовут?" }
     ],
     "stream": false
   }
   ```
3. **Send** → в ответе поле `message.content` (плюс статистика: `prompt_eval_count`, `eval_count`, `eval_duration`, `total_duration`)
4. Диалог из двух ходов — просто дописать в `messages` ответ ассистента и следующий вопрос:
   ```json
   {
     "model": "qwen2.5:3b",
     "messages": [
       { "role": "user", "content": "Меня зовут Алекс." },
       { "role": "assistant", "content": "Привет, Алекс!" },
       { "role": "user", "content": "Как меня зовут?" }
     ],
     "stream": false
   }
   ```
5. Вариант с OpenAI-совместимым API (если захочется показать совместимость): **POST** `http://localhost:11434/v1/chat/completions`, тело того же вида, ответ — в `choices[0].message.content`

Кириллица в Postman естественна — он шлёт UTF-8, никаких charset-танцев, в отличие от PowerShell.

## Задание 2 (день 27): веб-чат с локальной LLM и памятью (окно 10 сообщений)

Веб-приложение week6 (Spring Boot, порт 8080) работает **полностью локально**: модель qwen2.5:3b через Ollama,
облачные API не нужны (в pom deepseek-стартер заменён на `spring-ai-starter-model-ollama`,
в yaml `spring.ai.ollama.base-url: http://localhost:11434`).
Память — `MessageWindowChatMemory` на 10 сообщений, хранится в PostgreSQL (`SPRING_AI_CHAT_MEMORY`, миграция 001),
переживает рестарт приложения; cid — в cookie `cid` (30 дней).

Как проверить (снять на видео):

1. Поднять Ollama (`ollama serve`) — модель уже скачана; запустить week6 (порт 8080)
2. Открыть http://localhost:8080/chat
3. Память в окне: «Привет! Меня зовут Алекс, мы готовим ТЗ на брошюру о заклинаниях.» → пара вопросов →
   «Как меня зовут и над чем мы работаем?» — вспоминает и имя, и тему
4. Вытеснение за окном: задать ещё 3–4 нейтральных вопроса (перевод, столица, арифметика) —
   10-сообщений-окно вытесняет первый обмен → «Как меня зовут?» — модель честно отвечает, что не знает
5. БД: `SELECT conversation_id, COUNT(*) FROM SPRING_AI_CHAT_MEMORY GROUP BY 1;` — в каждой беседе не больше 10 строк
6. Перезапустить приложение → история на месте (хранится в PostgreSQL); «Новый диалог» — чистая беседа

Замечено (квирк крошечной модели, не баг): qwen2.5:3b иногда вставляет иероглифы в русские слова («打算е»)
— у крупных моделей такого нет; для видео просто переспросить.

## Задание 3 (день 28): локальная LLM + RAG

RAG-пайплайн из недели 5, переведённый на локальную генерацию: retrieval уже был локальным (эмбеддинги
paraphrase-multilingual-MiniLM через ONNX, 384d; косинус по чанкам в Java), теперь и генерация локальная —
qwen2.5:3b через Ollama. Для сравнения оставлен облачный deepseek-v4-flash: обе модели получают ОДИННАКОВЫЙ
контекст (топ-6 чанков) и одинаковый промпт, отвечают бок о бок.

Как проверить (снять на видео):

1. Ollama (`ollama serve`) + week6 на 8080 (нужен VPN только для облачной колонки; `DEEPSEEK_API_KEY` в User-scope)
2. Открыть http://localhost:8080/rag → «Индексировать корпус» → «Проиндексировано чанков: 33»
3. «Спросить обе модели»: «Какое заклинание отделяет душу от тела и почему оно запрещено?»
   - локально: формула есть, но с опечаткой («Капут тынетутут») и менее точным объяснением
   - облако: точная формула + причина запрета (список Ста)
4. «Прогнать 6 контрольных на обеих моделях» — таблица вопрос/есть-нет/секунды.
   Ожидание (прогон 10.10.2026): локально 5/6 в среднем 2,1 с/ответ, облако 6/6 в среднем 1,2 с/ответ;
   единственный промах локальной — «Как наложить на человека молчание?» (Капут Молчанус)
5. Нюанс для видео: ПЕРВЫЙ запрос к локальной модели холодный (~45 с — Ollama грузит модель в память),
   дальше ответы 1–5 с; если Ollama простояла 5+ минут — снова холодный старт

Ключевая грабля пайплайна (обе колонки отвечали «не нашёл»): чанкер резал корпус только по `##`,
целая секция «Запрещённые заклинания» (4600 симв., вперемешку нерелевантные заклинания) размывала
эмбеддинг — чанк с «Капут тынетут» не попадал в топ-6. Лечение: резать по всем уровням заголовков
(`###`, `####` тоже), путь разделов в поле section + название раздела в тексте чанка.
