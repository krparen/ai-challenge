## Задание 2

Как проверить:

1. Открыть коммит 54ed0f77e81ea404bf5fe99d0a523992836ecc21
2. Запустить service2 (порт 8081) — это mock REST API + MCP-сервер над ним
3. Опционально: проверить REST напрямую — http://localhost:8081/mock/getColor и http://localhost:8081/mock/getNumberFromZeroToNine (случайные цвет и число)
4. Запустить demo_application (порт 8080) — это MCP-клиент
5. Перейти на http://localhost:8080/mcp
6. «Запросить список инструментов» — увидеть DeepWiki (3 инструмента) и mock-api (getColor, getNumber)
7. Нажать «Вызвать getColor и getNumber» — увидеть результаты вызова через MCP и составленную из них фразу

Примечание: если service2 перезапускали при работающем demo_application, первый вызов вернёт ошибку «MCP session with server terminated» — нажмите кнопку ещё раз, клиент переподключится.

## Задание 3

Как проверить:

1. Открыть коммит f875af3d4e679d22150f784921a36f59ef368662
2. Запустить service2 (порт 8081) — фоновый сборщик каждые 5 с пишет пробы цвета/числа в таблицу mock_samples (БД challenge_week4_s2)
3. Запустить demo_application (порт 8080)
4. Перейти на http://localhost:8080/mcp
5. «Запросить список инструментов» — у mock-api появился третий инструмент getSummary
6. Внизу страницы блок «Автосводка от mock-api»: раз в 5 секунд через MCP запрашивается getSummary, новый результат заменяет старый, под ним timestamp «обновлено: HH:mm:ss»
7. Убедиться, что сводка растёт (счётчик проб увеличивается) и timestamp обновляется

Примечание: если service2 перезапускали при работающем demo_application, первый опрос автосводки покажет ошибку сессии — через 5 секунд блок обновится сам.

## Задание 4

Как проверить:

1. Открыть коммит c1be554f77731eff95594a841c180ecd389dd50e
2. Запустить service2 (порт 8081) и demo_application (порт 8080)
3. Перейти на http://localhost:8080/mcp
4. «Запросить список инструментов» — у mock-api теперь 5 инструментов, у summarizeText и saveToFile описаны входные параметры (text)
5. Нажать «Запустить пайплайн» — одной кнопкой выполняется цепочка getSummary → summarizeText → saveToFile, на странице видны результаты всех трёх шагов
6. Проверить передачу данных: шаг 2 (сводка) содержит текст шага 1, шаг 3 возвращает абсолютный путь к файлу
7. Открыть файл по пути из шага 3 — в нём сохранена сводка из шага 2 (новый файл создаётся при каждом нажатии)

Примечание: каталог saved отсчитывается от рабочей папки процесса service2 (из IDE это корень проекта — файлы появятся в ai-challenge/saved).
